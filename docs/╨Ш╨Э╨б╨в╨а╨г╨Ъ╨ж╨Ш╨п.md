# FIZZAROLLIO — как подключить базу данных (по одному шагу)

Что делаем: создаём новый проект Supabase, вставляем в него готовые файлы и один раз вписываем два публичных значения в сайт.
Делай шаги строго по порядку. Если что-то не получилось — остановись и напиши мне, на каком шаге и что видишь на экране (скриншот подойдёт).

**Правило безопасности:** никогда не присылай мне и никому не показывай пароль базы данных и ключ `service_role` / `secret`. Мне они не нужны.

---

## Шаг 1. Создай проект Supabase
1. Открой supabase.com и войди (или зарегистрируйся).
2. Нажми **New project**.
3. Название: `fizzarollio`. Регион: ближайший к твоим слушателям (например, Frankfurt).
4. Придумай **Database Password** и сохрани его в менеджер паролей. Больше он нигде не понадобится.
5. Нажми **Create new project** и подожди 1–2 минуты.

## Шаг 2. Создай таблицы (SQL)
В левом меню открой **SQL Editor**. Потом три раза подряд:
1. Нажми **New query**.
2. Открой файл из папки `supabase/migrations/` в любом текстовом редакторе, скопируй ВСЁ содержимое, вставь в окно.
3. Нажми **Run**. Должно появиться «Success».

Порядок строго такой:
1. `20261119000001_profiles.sql`
2. `20261119000002_cards.sql`
3. `20261119000003_seed.sql`

Проверка: открой **Table Editor**. Должны быть таблицы `profiles`, `cards`, `card_templates`, `rarity_weights`. Рядом с каждой не должно быть надписи «RLS disabled».

## Шаг 3. Включи вход по почте и подтверждение
1. **Authentication → Sign In / Providers → Email**.
2. Включено: **Enable Email provider**.
3. Включено: **Confirm email** (подтверждение почты).
4. Минимальная длина пароля: поставь **8** (название пункта может чуть отличаться в новой версии панели).
5. Сохрани (**Save**).

## Шаг 4. Укажи адрес сайта
Сначала нужно, чтобы сайт был в интернете (см. шаг 8 про хостинг). Вернись сюда, когда будет адрес вида `https://твой-сайт.netlify.app`.
1. **Authentication → URL Configuration**.
2. **Site URL**: адрес твоего сайта (без слэша в конце).
3. **Redirect URLs → Add URL**: тот же адрес и ещё такой же со слэшем в конце.
4. Сохрани.

## Шаг 5. Загрузи серверную функцию
1. Левое меню: **Edge Functions → Deploy a new function → Via Editor**.
2. Название строго: `claim-card`.
3. Замени весь код в редакторе на содержимое файла `supabase/functions/claim-card/index.ts`.
4. Нажми **Deploy**.
5. Открой настройки этой функции и **выключи «Verify JWT»** (если такой переключатель есть). Функция сама проверяет вход пользователя.

## Шаг 6. Укажи, какому сайту разрешено вызывать функцию
1. **Edge Functions → Secrets** (или Project Settings → Edge Functions).
2. Добавь секрет: имя `ALLOWED_ORIGIN`, значение — адрес сайта, например `https://твой-сайт.netlify.app`.
   Для проверок на своём компьютере можно через запятую добавить `http://localhost:8000`.
3. Сохрани.

## Шаг 7. Впиши два публичных значения в сайт
1. В Supabase: **Project Settings → API** (или «API Keys»).
2. Скопируй **Project URL**.
3. Скопируй ключ **anon public** (в новой панели он может называться **Publishable key**).
4. Открой файл `config.js` и вставь их между кавычками.

Этот ключ публичный, его можно держать в сайте. А вот `service_role` / `secret` НЕ вставляй никуда.

## Шаг 8. Выложи сайт в интернет
Открывать `index.html` двойным щелчком не подойдёт: вход и карточки работают только с настоящего адреса.
Самый простой вариант: **Netlify Drop** (app.netlify.com/drop). Перетащи туда папку сайта (папку `supabase` и `docs` можно удалить перед загрузкой, сайту они не нужны). Получишь адрес. Вернись к шагам 4 и 6 и впиши этот адрес.

## Шаг 9. Настрой почту (это важно!)
Стандартная почта Supabase годится только для проверок: писем очень мало в час, а в новых проектах она отправляет письма только участникам твоей команды Supabase. Настоящим слушателям письма не дойдут. Нужна своя почтовая служба (SMTP).

1. Заведи аккаунт в почтовой службе: например Resend или Brevo (у обеих есть бесплатный тариф).
2. Подтверди в ней свой домен или адрес отправителя (служба сама покажет, какие записи добавить в настройки домена).
3. Получи данные SMTP: сервер (host), порт, логин, пароль.
4. В Supabase: **Authentication → Emails → SMTP Settings → Enable custom SMTP**. Вставь эти данные и адрес отправителя, например `no-reply@твой-домен`.
5. Здесь же, во вкладке **Templates**, можно изменить тексты писем. Главное: в письмах должна остаться ссылка `{{ .ConfirmationURL }}`.

Пример текста письма «Confirm signup»:
```
<h2>FIZZAROLLIO: подтверди почту</h2>
<p>Чтобы войти в систему, нажми на ссылку:</p>
<p><a href="{{ .ConfirmationURL }}">ПОДТВЕРДИТЬ ПОЧТУ</a></p>
```
Пример для «Reset password»:
```
<h2>FIZZAROLLIO: новый пароль</h2>
<p><a href="{{ .ConfirmationURL }}">ЗАДАТЬ НОВЫЙ ПАРОЛЬ</a></p>
<p>Если это был не ты, просто проигнорируй письмо.</p>
```

## Шаг 10. Проверь, что всё работает
1. Открой сайт, нажми «Войти в мой мир», в верхней панели появится кнопка **ВХОД**.
2. Зарегистрируйся: ник, почта, пароль. Должно появиться «ПРОВЕРЬ ПОЧТУ».
3. Открой письмо и нажми ссылку. Лучше в том же браузере и на том же устройстве, где регистрировался. Если открыл в другом, просто войди по паролю.
4. Войди → **ПОЛУЧИТЬ КАРТОЧКУ**. Должна появиться карточка с номером вида `FZ-000001`.
5. Нажми «Выйти» и войди снова: карточка должна быть та же.
6. Нажми «Забыл пароль?», получи письмо, задай новый пароль.
7. В Supabase → Table Editor → `cards` должна быть одна строка на пользователя.

---

## Что можно менять
- **Названия, описания, символы карточек**: Table Editor → `card_templates`.
- **Шансы редкостей**: Table Editor → `rarity_weights` (чем больше число, тем чаще).

## Как устроена защита
- Пароли хранит Supabase Auth, в твоих таблицах их нет.
- В браузере только публичный ключ. Ключ `service_role` используется лишь внутри серверной функции.
- Включена RLS: пользователь видит только свою карточку и свой профиль, менять карточки из браузера нельзя.
- Карточку выдаёт только серверная функция `claim-card`, после проверки входа и подтверждённой почты.
- `UNIQUE(owner_id)` в базе не даст создать вторую карточку, даже если нажать кнопку много раз. Повторный запрос возвращает ту же карточку.
